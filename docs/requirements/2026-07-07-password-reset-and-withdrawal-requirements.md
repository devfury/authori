# 요구사항정의서 — 비밀번호 재설정 및 회원 탈퇴(계정 비활성화·유예 삭제)

> **Status:** Draft
> **Owner:** Jinho Lee
> **Created:** 2026-07-07
> **Updated:** 2026-07-07

## 1. 문제 정의

Authori는 멀티테넌트 OAuth2 인증 서비스로, 엔드유저의 공개 회원가입(`register`)과 이메일 인증(`verify-email`)은 지원하나 다음 두 흐름이 없다.

- **비밀번호 재설정**: 비밀번호를 잊은(=로그인하지 못하는) 사용자가 스스로 비밀번호를 되찾을 수단이 없다.
- **회원 탈퇴**: 서비스 제공자(테넌트) 앱에서 탈퇴를 요청했을 때 계정을 정리하는 표준 절차가 없다. 즉시 삭제는 오조작·복구 요청에 취약하고, 방치는 개인정보 보관 리스크가 된다.

## 2. 목표

- 로그인하지 않은 사용자도 호출할 수 있는 **공개 비밀번호 재설정 API**(토큰 인증 불필요)를 제공한다.
- 재설정은 이메일로 발송된 일회용 토큰 링크를 통해서만 완료되며, Authori 프론트엔드에서 새 비밀번호를 설정한다(이메일 인증과 유사한 2단계).
- 서비스 제공자가 M2M API로 계정을 **비활성화(탈퇴)** 하면, 일정 유예기간 경과 후 계정이 **자동 삭제**되도록 한다.
- 유예기간은 **테넌트별 설정**으로 지정할 수 있으며 기본값은 **30일**이다.

## 3. 사용자/역할/권한 범위

| 주체 | 흐름 | 인증 |
|------|------|------|
| 엔드유저(비로그인) | 비밀번호 재설정 요청·확정 | 없음(공개 엔드포인트) + 이메일 일회용 토큰 |
| 서비스 제공자(M2M 클라이언트) | 계정 비활성화(탈퇴 요청) | client_credentials 토큰, scope `users:write` |
| 시스템(스케줄러) | 유예기간 경과 계정 삭제 | 내부 크론(무인) |

## 4. 기능 요구사항

### 4.1 비밀번호 재설정

| ID | 요구사항 |
|----|----------|
| FR-1 | 공개 엔드포인트 `POST /t/:tenantSlug/oauth/password-reset/request`(인증 불필요)로 `{ email }`을 받아 재설정을 시작한다. |
| FR-2 | 재설정은 항상 **이메일로 발송된 일회용 토큰**을 통해서만 완료된다. 토큰은 `sha256` 해시로 저장한다. |
| FR-3 | 공개 엔드포인트 `POST /t/:tenantSlug/oauth/password-reset/confirm`(인증 불필요)로 `{ token, newPassword }`를 받아 토큰 검증 후 비밀번호를 변경한다. |
| FR-4 | **계정 열거 방지**: 메일 인프라가 정상인 상황에서 요청 이메일에 해당하는 계정이 없으면, 계정 존재 여부를 노출하지 않도록 **성공 응답**을 반환하고 메일은 보내지 않는다. |
| FR-5 | **발송 실패 안내**: SMTP 미설정, 또는 발송 서버·인증정보 변경 등으로 메일을 보내지 못하는 경우, 사용자에게 **발송 실패**를 알린다(계정 존재 여부와 무관한 인프라 오류로 처리). |
| FR-6 | `confirm` 시 새 비밀번호는 테넌트 `passwordMinLength` 정책을 만족해야 한다. |
| FR-7 | `confirm` 성공 시 해당 사용자의 활성 access/refresh 토큰을 폐기하여 기존 세션을 무효화한다. |
| FR-8 | 재설정 토큰은 만료시간을 가지며(기본 1시간), 만료·사용완료·위조 토큰은 거부한다. 사용된 토큰은 재사용할 수 없다. |
| FR-9 | 재설정 확정은 비밀번호만 변경하며 계정 `status`는 바꾸지 않는다. |
| FR-10 | 두 공개 엔드포인트 모두 요청 속도 제한(throttle)을 적용한다. |
| FR-11 | 프론트엔드에 요청 폼(`/forgot-password`)과 새 비밀번호 설정 화면(`/reset-password?token=&tenantSlug=`)을 제공한다. |

### 4.2 계정 비활성화(탈퇴) 및 유예 후 삭제

| ID | 요구사항 |
|----|----------|
| FR-12 | 서비스 제공자는 기존 M2M 엔드포인트 `POST /t/:tenantSlug/api/users/:userId/deactivate`(scope `users:write`) 호출로 탈퇴를 요청한다. 신규 엔드포인트는 만들지 않는다. |
| FR-13 | 비활성화 시 `status = INACTIVE`로 변경하고, 비활성화 시각(`deactivatedAt`)을 기록한다. |
| FR-14 | 비활성화 시 해당 사용자의 활성 access/refresh 토큰을 즉시 폐기한다. |
| FR-15 | 테넌트의 이메일 인증 옵션(`emailVerificationRequired`)이 켜져 있으면 비활성화 안내 메일을 발송한다. |
| FR-16 | 비활성화 유예기간(`accountDeletionGracePeriodDays`, 테넌트 설정, 기본 30일)이 경과한 INACTIVE 계정은 스케줄러가 자동 삭제한다. |
| FR-17 | 유예기간 이내에 계정이 다시 활성화(`activate`)되거나 잠금 해제(`unlock`)되면 `deactivatedAt`을 초기화하여 예약된 삭제를 취소한다. |
| FR-18 | 자동 삭제는 기존 `usersService.delete()` 경로를 재사용하여 관련 데이터(Consent/토큰/인가코드/프로필/사용자)를 함께 정리한다(하드 삭제). |
| FR-19 | 이메일 미인증 상태로 남아 있는 INACTIVE 계정(비활성화로 인한 것이 아닌, `deactivatedAt`이 없는 계정)은 자동 삭제 대상에서 제외한다. |

### 4.3 스케줄러 다중 인스턴스 안전성

| ID | 요구사항 |
|----|----------|
| FR-20 | API 컨테이너가 여러 개(레플리카)여도 삭제 스윕이 중복 실행되지 않아야 한다. |
| FR-21 | 스윕 진입 시 Postgres advisory lock으로 단일 인스턴스만 실행하도록 하고, 잠금을 얻지 못한 인스턴스는 조용히 종료한다. |
| FR-22 | 삭제 대상 조회는 `FOR UPDATE SKIP LOCKED`와 멱등 삭제로 처리하여, 만에 하나 동시 실행되어도 같은 계정을 중복 처리하거나 오류가 나지 않도록 한다. |

## 5. 비기능 요구사항

- **보안**: 재설정 엔드포인트는 인증이 없으므로, 계정 소유 증명은 **이메일로 전달된 일회용 토큰 소지**로만 성립한다. 이메일 없이 임의 계정의 비밀번호를 바꿀 수 있는 경로를 두지 않는다.
- **크래시 안전**: advisory lock은 트랜잭션 스코프(`pg_try_advisory_xact_lock`)로 사용해 프로세스가 도중에 죽어도 잠금이 누수되지 않는다.
- **하위호환**: 기존 사용자·테넌트는 신규 컬럼이 기본값(또는 null)으로 마이그레이션되며 기존 흐름에 영향이 없다.
- **일관성**: 메일 발송은 기존 전역 SMTP 설정과 테넌트별 `mailFrom`/`mailDevRedirectTo` 규칙을 그대로 따른다.
- **관측성**: 비활성화·삭제·비밀번호 재설정은 AuditLog에 기록한다.

## 6. 제외 범위 (Out of Scope)

- 이메일/아이디 찾기 API(요청 철회됨).
- SMTP 미설정 시 재설정 UI를 이메일 없이 바로 노출하는 기능(요청 철회됨).
- SMS/전화 등 이메일 외 재설정 채널.
- 소프트 삭제(soft delete)나 삭제 데이터 아카이빙.
- 관리자 콘솔에서의 비밀번호 재설정 대행(별도 흐름).

## 7. 성공 기준

- 비로그인 사용자가 이메일 링크를 통해 비밀번호를 재설정하고, 재설정 후 기존 세션이 무효화된다.
- 존재하지 않는 이메일로 요청해도 계정 존재 여부가 노출되지 않는다(정상 인프라 기준).
- SMTP 미설정/발송 실패 시 사용자에게 실패가 안내된다.
- M2M `deactivate` 호출 시 계정이 INACTIVE로 바뀌고 토큰이 폐기되며, 이메일 인증 옵션이 켜진 테넌트는 안내 메일을 받는다.
- 유예기간(기본 30일, 테넌트별 설정 가능)이 지난 비활성화 계정이 자동 삭제되고, 유예기간 내 재활성화 시 삭제가 취소된다.
- 다중 인스턴스 환경에서 삭제 스윕이 중복 실행되지 않는다.
- `bun run lint && bun run typecheck && bun run test && bun run build` 통과.
